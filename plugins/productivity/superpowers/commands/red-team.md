# Red Team

Red-team the given idea, design, or implementation to find weaknesses and failure modes.

## Instructions

1. Ask the user what to red-team if no target was provided
2. Activate the red-team-thinking skill
3. Understand the target thoroughly — read relevant code or documentation
4. Analyze from all adversarial angles: technical failures, logic flaws, human/process failures, and adversarial scenarios
5. Assess each finding by likelihood and impact
6. Categorize findings as Critical, High, Medium, or Low
7. Provide concrete mitigations for all Critical and High findings
8. Summarize with a clear count of issues and the top recommendation

Be constructive — the goal is to strengthen the target, not tear it down.
